Conectamos el mundo físico y digital

Arquitectura de VitaLink V3.2 y su relación con el proyecto integrador 14.

Arquitectura del sistema

Frontend web

HTML, CSS y JavaScript para las interfaces de gestión de medicamentos y la web publicitaria.

Abrir plataforma →

Backend y datos

Supabase proporciona autenticación, almacenamiento de registros en PostgreSQL y funciones de comunicación con el dispositivo.

Android

Capacitor 8 reutiliza la interfaz web en Android e incorpora soporte de notificaciones locales.

Aplicación Android →

Electrónica y firmware

ESP32 programado en C++ con Arduino, RTC DS3231, LCD I²C, LED, buzzer y pulsador. El soporte HX711 requiere calibración y validación.

Comunicación

El firmware contempla consultas de horarios y envío de confirmaciones mediante Wi-Fi y HTTPS a funciones de Supabase. La vinculación gestionada de V3.2 utiliza identificación del dispositivo y código de vinculación; su validación en el prototipo físico está pendiente.

Flujo de información

01 · Configuración

El usuario registra horarios desde la plataforma.

02 · Sincronización

El firmware consulta los horarios mediante HTTPS.

03 · Aviso y registro

El dispositivo genera avisos y puede enviar confirmaciones. Confirmar un aviso no demuestra ingesta.

Desarrollo académico

PSeInt

Diseño lógico del proyecto 14: siete operaciones de menú, validación HH:MM, estructuras de control, arreglos, matrices, funciones y subprocesos.

Java

Versión de consola del algoritmo: hasta diez medicamentos con uno a tres horarios por medicamento. Estados programado, emitido sin confirmar y confirmado. Los datos permanecen en memoria; no controla sensores ni sustituye la aplicación Android.

Electrónica

Firmware, documentación de conexiones y simulación electrónica del prototipo.

Ver simulación →

Repositorio académico

Publicación pendiente del repositorio público con las carpetas PSeInt, Java y Electrónica. No se publicarán credenciales ni datos personales de usuarios.
