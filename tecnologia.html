Conectamos el mundo físico y digital

Arquitectura de VitaLink V3.2 y su relación con el proyecto integrador 14.

Arquitectura del sistema

Frontend web

HTML, CSS y JavaScript para las interfaces de gestión de medicamentos y la web publicitaria.

Abrir plataforma →

Backend y datos

Supabase proporciona autenticación, almacenamiento de registros en PostgreSQL y funciones de comunicación con el dispositivo.

Android

Capacitor 8 reutiliza la interfaz web en Android e incorpora soporte de notificaciones locales.

Aplicación Android →

Electrónica y firmware

ESP32 programado en C++ con Arduino, RTC DS3231, LCD I²C, LED, buzzer y pulsador. El soporte HX711 requiere calibración y validación.

Comunicación

El firmware contempla consultas de horarios y envío de confirmaciones mediante Wi-Fi y HTTPS a funciones de Supabase. La vinculación gestionada de V3.2 utiliza identificación del dispositivo y código de vinculación; su validación en el prototipo físico está pendiente.

HARDWARE / VITALINK

Componentes y funciones

Conoce las entradas, el procesamiento y las salidas de VitaLink mediante sus componentes. Las imágenes son referencias del diseño; los modelos pueden variar respecto al montaje real.

ESP32 DevKit V1

Procesamiento y comunicación

Procesa las entradas del reloj y los sensores, ejecuta la lógica de recordatorios, controla las salidas y se comunica con la plataforma mediante Wi-Fi.

Ubahnverleih · CC0 1.0

RTC DS3231

Entrada · Tiempo

Proporciona la fecha y hora que el ESP32 compara con los horarios programados para activar los avisos.

Suyash.dwivedi · CC BY-SA 4.0

LCD 16×2 I²C

Salida · Pantalla

Muestra la hora, los estados del sistema, los avisos y el código de vinculación de seis dígitos.

Martinwguy · CC BY-SA 3.0

HX711

Entrada · Medición

Interpreta la señal de la celda de carga para que el ESP32 pueda medir el peso. Su uso requiere habilitación, calibración y validación física.

SparkFun · Foto de referencia del fabricante

Celda de carga

Entrada · Sensor

Detecta variaciones de peso a través del HX711. Requiere calibración y verificación; los cambios de peso no demuestran la ingesta de medicamentos.

Gannu03 · CC BY-SA 4.0

Buzzer activo

Salida · Sonido

Emite señales sonoras periódicas mientras hay un aviso de medicación pendiente.

Nvtj · CC BY-SA 3.0

Indicadores LED

Salida · Señales visuales

El LED rojo indica un aviso pendiente y el verde se enciende temporalmente cuando el sistema acepta una confirmación.

Evan-Amos · Dominio público

Pulsadores

Entrada · Interacción

El pulsador de confirmación permite registrar la atención de un aviso. Si se mantiene presionado al iniciar el ESP32 en modo gestionado, solicita la vinculación.

oomlout · CC BY-SA 2.0

Componentes complementarios

Servo (opcional)

Fuente y resistencias

Flujo de información

01 · Configuración

El usuario registra horarios desde la plataforma.

02 · Sincronización

El firmware consulta los horarios mediante HTTPS.

03 · Aviso y registro

Desarrollo académico

PSeInt

Diseño lógico del proyecto 14: siete operaciones de menú, validación HH:MM, estructuras de control, arreglos, matrices, funciones y subprocesos.

Consultar pseudocódigo →

Java

Traducción de consola aportada por el equipo: siete opciones de menú, hasta diez medicamentos con uno a tres horarios, validación de entradas y registro del estado de los avisos. Código compilado y probado con casos normales, inválidos y de capacidad máxima. Los datos permanecen en memoria; no controla sensores ni sustituye la aplicación Android.
